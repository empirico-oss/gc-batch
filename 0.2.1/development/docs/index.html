    Documentation

    Documentation is built using MkDocs with several plugins:

    • Material for MkDocs for the theme
    • mkdocs-macros for macros and variables

    Structure

    gc-batch/
├── docs/                # Markdown documentation files
│   ├── index.md         # Home page
│   ├── development/     # Development docs
│   └── guides/          # User guides
├── include/
│   └── mkdocs/
│       └── macros.py    # Custom macros
└── mkdocs.yml           # MkDocs configuration

    Writing Documentation

    Installing MkDocs Dependencies

    uv sync --group docs

    Adding New Pages

    New pages are added as markdown files in the docs/ folder. Pages must be included in the nav: section of mkdocs.yml:

    mkdocs.yml
    nav:
  - Home: index.md
  - Development: development/
  - Guides: guides/

    Viewing Changes Locally

    MkDocs includes a development server with live reloading:

    uv run mkdocs serve

    Then open http://localhost:8000 in your browser.

    Building Static Site

    To build the static documentation site:

    uv run mkdocs build

    The output will be in the site/ directory.

    Deploying Documentation

    The published site is versioned with mike and tracks releases, not main. Releasing deploys that version and moves the stable alias that https://empirico-oss.github.io/gc-batch/stable/ resolves to. The workflow itself is .github/workflows/mkdocs.yaml.

    Pre-releases do not publish, so a release candidate never becomes stable.

    To publish a preview of a branch — or of a pre-release — run the Build and Deploy Docs workflow from the Actions tab; it deploys the branch under its own name, plus any alias you pass as the alias input.

    Do not run mkdocs gh-deploy

    It overwrites the whole gh-pages branch with a single unversioned build, destroying the version switcher and every published release. Use mike if you need to deploy by hand:

    uv run --only-group docs mike deploy --push --update-aliases 1.2.3 stable
